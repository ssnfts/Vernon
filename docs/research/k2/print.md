# k2 review: print area (split, cut, grid, joints, bed fit, 3MF)

Vetted 2026-10-22 against the real Vernon API (vernon-core geometry.rs and report.rs, vernon-graph node.rs, param.rs, data.rs, graph.rs, registry.rs, vernon-io lib.rs, vernon-nodes-geo helpers, docs/specs/slicing-printing.md). Crate facts come from `cargo info` plus the unpacked crate sources. No web searches were used: k2's claims contain no case names, courts or years, so there is nothing legal to verify beyond licence strings. k2 saw no Vernon code, so most of its structure does not apply. Its geometry ideas are partly sound and partly buggy.

## 1. Summary

1. k2 designed for a different engine: a `Vertex` struct with a key, a `MultiMesh` variant, `modifier_factory`, `Core::new`, mutable node state, a per-node `fingerprint()`. Vernon has none of these: `Geometry` is points, prims and attributes; nodes are stateless `NodeOp`; the graph caches on a hash of params and input signatures; multi-part results are one `Geometry` with prim Int `part`.
2. Keep k2's ideas, not its code: split by key or connectivity (as `part` writers), plane cut, grid split, dovetail, dowel, bed fit. Several k2 algorithms are wrong as written: the plane split drops the quad (area loss), mixes index spaces, never caps, and k2's dovetail narrows toward the tip and so cannot lock. Its panel bound 2^n is wrong for n >= 4 (true bound: C(n,0)+C(n,1)+C(n,2)+C(n,3)).
3. Reject everything that pulls in OpenCascade (LGPL-2.1, C++ via cxx and build.rs, `builtin` feature statically builds it), the threemf and obj crates (redundant, licences mis-stated) and nalgebra (not a Vernon dependency, MSRV 1.89 against workspace 1.80).
4. Gating must go through `Report` metrics with limits (`part_count`, `seam_area_mm2`, `fit_margin_mm >= 0`, `open_edges <= 0`, `unassigned_prims <= 0`). k2 prints text only and silently drops or scales.
5. Blocking fact outside k2: `vernon-io` does not compile yet. At review time `lib.rs` declared `mod threemf; mod xml; mod xyz; mod zip;` with the four files absent (E0583 x4). They were added during the session (another stage, 2026-10-22 14:09 to 14:14) but the last `cargo check -p vernon-io --offline` still fails: E0432 unresolved `crate::tri` import and E0503 x3 in `zip.rs` (borrow of `uncomp`, `comp`, `local_offset`). A working 3MF writer and reader is the prerequisite for all print output. k2 supplied nothing for 3MF, slicer hand-off or G-code flavours (its final reply was empty), so those come from docs/specs/slicing-printing.md only.

Verdict counts over 61 claims: ACCEPT 3, ADAPT 39, REJECT 19.

## 3. Bugs and hazards

In k2's code or claims (from the summaries; k2's raw code was not available):

1. Plane split: quad on the two-vertex side reduced to one triangle (area loss), local and global indices mixed, intersection vertices created per triangle (not shared), no caps, so output is neither closed nor printable. Tests assert counts only, so all of this passes.
2. Zero normal: `Plane::new` yields NaN and the whole mesh lands on the positive side.
3. Panel ids documented as a bit mask but never computed; `keep_original` is dead.
4. Dovetail narrows toward the tip (cannot lock), repeats a vertex, caps a non-convex polygon by fan, extrudes along the wrong axis, and the joint solids overlap the panels.
5. Cylinder winding inverted on every face; 24 sides under-fill by 1.14%.
6. Bed fit: no Z check (so tests pass by standing parts upright), one-sided margin, scaled fit can beat an unscaled fit, inverted scale preference, `max_scale` limits the wrong direction, placement comment says centre but code corner-aligns, JSON lacks translation.
7. Count and arithmetic errors in docs and tests (120 vs 30 panels, 9 vs 7 interfaces, 12 vs 24 pins, 2^n vs C(n,<=3)). Dowel radius test passes for any radius above 0.707 mm.
8. Dependencies and licences mis-stated: threemf is 0BSD (not MIT), obj is Apache-2.0 (not MIT), nalgebra is not in the workspace and needs rustc 1.89 (workspace 1.80), OCCT is statically linked by default.
9. Statefulness: cook() writes into self and fingerprint reads state from a previous cook; both are impossible and unnecessary in Vernon.
10. Unwelded meshes explode into per-triangle components under edge connectivity; mixed-key triangles silently disappear.

Vernon-side hazards found while vetting:

11. `vernon-io` does not compile: modules `threemf`, `xml`, `xyz`, `zip` were declared in lib.rs with no files (E0583 x4). The files now exist (written by another stage) but still fail `cargo check --offline` with E0432 (`crate::tri` import not declared as a module in lib.rs) and E0503 x3 in `zip.rs` (mutable borrow passed together with a read of the same variable). The `.pts`/XYZ and 3MF paths in lib.rs depend on them.
12. Graph cache keys ignore file contents (K44): plane files, 3MF inputs and `geo.file_read` can go stale.
13. `ParamKind` has no folder picker and no multi-int widget; designs that need them must use `Path`/`Str`/three `Int`.
14. nodes-print has no dependency on vernon-nodes-geo, where `edge_counts`, `triangulate_polygon`, `compact_points`, `make_tube` and `fuse_points` live (all `pub`). Add a path dependency (Apache-2.0, workspace-internal) rather than copying.
15. 3MF reader must bound decompressed size and entry count (hand-written zip parser, spec asks for ZIP64 and streaming); an unbounded inflate is a zip-bomb vector.
16. No legal case claims appear in this range; the only legal-adjacent statements (OCCT LGPL linking, licence sufficiency) are UNVERIFIED and need review before any OCCT use, which this review rejects anyway.
