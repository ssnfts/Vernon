# Vernon

Open-source, node-based 3D toolkit for the **scan → surface → print → simulate**
workflow used to design 3D-printed car body kits. Vernon has a familiar
DCC-style interface (quad viewports, command panel, modifier stack) and a
procedural node graph underneath. Every stage emits a numeric report
(deviation percentile, bed-fit margin, CdA, safety factor, surface
temperature vs heat-deflection temperature, lap time...) that the next stage
checks.

Status: **pre-alpha**. Every pipeline tool exists as a node with real inputs,
outputs and parameters. Most nodes run their real algorithm; the *white-box*
ones still run a placeholder, cook anyway and say so in a warning. The full
catalogue, with what each node emulates, is in [docs/NODES.md](docs/NODES.md)
(generated by `vernon-cli list --markdown`).

## What Vernon does, step by step

A body kit starts as a scan of the real car and ends as printed, bolted-on
parts whose airflow, strength, heat and lap-time effect have been checked.
Each step below is a group of nodes. Each one passes geometry and a numeric
`Report` to the next, and a step's gates (limits on its report metrics) must
pass before the following step trusts its output.

1. **Geometry basics.** Primitives, a test car panel, transforms, merge,
   mirror, normals, noise, and reading and writing OBJ, STL, PLY, 3MF and XYZ.
   These are the building blocks every other step uses.
2. **Capture.** Import scans (PLY/OBJ/STL/XYZ, E57, LAS) or run external
   photogrammetry (COLMAP) on photos. Scale bars and coded markers fix
   real-world scale. Feature registration and a robust multi-scan pose graph
   align several scans into one. *Reports:* registration residuals, marker
   scale error, scan coverage.
3. **Clean and align.** Decimate, remesh, remove outliers and smooth. Align the
   scan to the car's coordinate frame with ICP. Build a certified conservative
   wrap. Measure signed deviation against the reference. *Gate:* deviation
   percentile within tolerance.
4. **Mesh to surface.** Refine regions, remesh with field-aligned quads, fit
   connected B-spline patch layouts and recognise analytic primitives. Check
   continuity, then cut sections, loft and thicken the kit's surfaces. Export
   STEP for CAD. *Gate:* surface-to-scan deviation.
5. **Split and print.** Cut the kit along projected body lines and search for
   a partition that fits the printer bed. Add dovetail, dowel and plug keys and
   strain-screened snap hooks. Write 3MF packages, slicer presets and G-code
   checks. *Gates:* bed-fit margin, snap-hook strain.
6. **Airflow (CFD).** Prepare the vehicle, measure frontal area and build a
   virtual wind tunnel with moving ground and rotating wheels. Plan mesh
   refinement and write a complete OpenFOAM case. Run snappyHexMesh and
   simpleFoam in WSL when asked. Read force coefficients, check convergence
   and plot Cp maps. *Reports:* Cd, Cl, CdA, mesh quality, convergence. The
   published DrivAer benchmark validation (WP9) is in progress, see below.
7. **Structure (FEA).** Use printed orthotropic materials with temperature
   derating. Model mounts and aero and bump loads, write CalculiX decks or use
   the built-in reference solver, then read results. *Gate:* safety factor at
   every mount.
8. **Solar and heat; flattening.** Compute sun position, weather files, sky
   matrix and incident radiation, then a surface energy balance. *Gate:*
   surface temperature vs the material's heat-deflection temperature. The
   flatten tools cut seams and unroll panels (conformal or as-rigid-as-possible),
   report strain and map the pattern back, for wraps and composite layups.
9. **Performance.** Turn CdA and ClA into aero loads, top speed and point-mass
   lap times with sweeps. Then check the claim against reality: coastdown fit,
   pressure-tap comparison, tuft classification. *Gate:* the simulated change
   must stand out from the measurement noise.

The [example pipeline](#example-pipeline) runs all nine steps on a synthetic
fender in one graph.

## Example pipeline

[examples/bodykit_pipeline.vrn](examples/bodykit_pipeline.vrn) runs the
whole chain on a synthetic fender: car panel → noisy, misplaced scan copy →
ICP alignment → deviation report and tolerance gate → freeform patch fit and
surface deviation → 3 mm shell → grid split, bed fit and 3MF → CFD case →
FEA deck → solar surface temperature vs HDT → flattening strain → vehicle,
aero loads and top speed. One air state (density, design dynamic pressure)
flows from the airflow stage into the performance table and on into the
structural aero load.

`cook` ends with a gate summary: every report metric outside its limit, with
value, limit and margin. It exits with 1 when a node fails and 3 when a gate
fails that the scene does not list under the node's `expect_fail`. The example
lists five expected gates: the single panel has no wheels, the built-in solid
mesher is a placeholder, and the airflow case is written but not solved, so
there are no solver forces yet. `--ignore-gates` keeps the exit code at 0.

```powershell
cargo run -p vernon-cli -- cook examples/bodykit_pipeline.vrn --out deviation.obj
cargo run -p vernon-cli -- list            # node types by stage
cargo run -p vernon-cli -- info clean.icp_align
cargo run -p vernon -- examples/bodykit_pipeline.vrn
```

In the app the same graph is under **Pipeline > Replace Scene with Demo**
(clears the scene first) or **Pipeline > Add Demo Copy** (adds a second copy).

## Getting started

Windows 10/11 with the Rust GNU toolchain is the supported development setup.
[docs/SETUP.md](docs/SETUP.md) takes a fresh PC from nothing to a passing
build, and then optionally to the WSL/OpenFOAM CFD environment.

```powershell
.\scripts\setup\setup-dev.ps1 -WriteCargoConfig   # checks the toolchain; installs nothing
. .\scripts\dev-env.ps1                            # every new shell
cargo run -p vernon
```

The viewports render with `vernon-render` (wgpu, depth-tested, MSAA); set
`VERNON_RENDERER=cpu` to use the CPU painter fallback. On Linux or macOS
plain `cargo` works.

## Checks and long runs

Definition of done for every change:

```powershell
cargo build --workspace
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo run -p vernon-cli -- cook examples/bodykit_pipeline.vrn
cargo run -p vernon-cli -- list --markdown > docs/NODES.md
```

The same queue, and long real-tool runs, can run as a hidden background
worker that survives chat interruptions. It saves logs and source fingerprints
under `scratch/continuation/runs/<run-id>/`:

```powershell
.\scripts\verification\start-verification.ps1 -Profile full -RunId full-YYYYMMDD-a -JobTimeoutSeconds 2400
.\scripts\verification\verification-status.ps1 -Json
```

## CFD validation (work package 9)

Vernon's airflow stage is being validated against the published TUM DrivAer
replication: 16 m/s, Cd targets of 0.275 for the fastback, 0.319 for the estate
and 0.277 for the notchback. Results must fall within a 5% band, use a 12M-cell
half-model minimum, pass a three-grid study and meet strict convergence. The
fine 12.06M-cell Fastback mesh is built and passes its quality gates. No
solver has run on it yet. The next steps (Stages 0–3) are in
[docs/CFD-RUNBOOK.md](docs/CFD-RUNBOOK.md). Their plan and estimates are in
[docs/superpowers/plans/2026-11-04-wp9-solver-run.md](docs/superpowers/plans/2026-11-04-wp9-solver-run.md).
